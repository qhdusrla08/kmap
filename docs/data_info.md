## 2. 공정과 현장 맥락

- **제품** : 분무건조공법으로 만든 **분말유크림** (식품제조업체 H사) [명시]
- **공정** : 포장공정의 마지막 단계인 X-ray 비전검사. 소비자에게 가기 전 **최종 품질검사**입니다 [명시]. 그래서 미검은 곧 시장 유출로 이어집니다.
- **장비** : X-ray 이물검출기 3대(1·2·3호기) [명시]
- **현장의 문제(Pain point)** [명시]
  - **미검** : 불량이 있는데 양품(OK)으로 판정하는 것 → 이 프로젝트의 **False Negative**
  - **과검** : 양품인데 불량(NG)으로 판정하는 것 → 이 프로젝트의 **False Positive**
  - 현장은 이를 막으려고 이중·삼중 검사를 합니다. 그 결과 라인 흐름이 바뀌고 중복 작업 비용이 들지만, 그래도 미검 가능성은 남습니다.
- **현장 요구** : 장비를 교체하지 않고, 수집 데이터에 AI 분석을 더해 판정 오류를 보완하는 것 [명시]
- **가이드북이 밝힌 한계** : 분석이 SD 카드에서 옮긴 이미지로 하는 **사후 분석**이라는 점. 실시간 적용에는 수집 모듈과 탐지 모듈의 통합이 필요하다고 적혀 있습니다 [명시]. 보고서 §4 "현장 활용방안"의 출발점으로 쓸 수 있습니다.

## 3. 수집 방식과 그 함의 ★ 가장 중요

- **수집 장비** : X-ray 이물검출기의 SD 카드에 자동 저장된 파일을 PC로 옮겨 수집 [명시]
- **수집 기간** : 2020-06-23 ~ 2020-09-22 (약 3개월) [명시]
- **수집 주기** : 불규칙. **검사장비가 불량으로 판정한 제품만 이미지로 저장** [명시]
- **양품 이미지는 따로 수집되지 않았습니다** [명시]

### 함의

1. **모든 BMP는 "장비가 NG로 판정한" 이미지입니다** [추론]
   - 데이터셋에 진짜 양품(이물 없음)이 거의 없거나 전혀 없을 수 있습니다.
   - 그러면 이미지 단위의 이물 유무 분류, FP(과검) 분석, 임계값 설계에 필요한 **음성 샘플이 부족**합니다.
2. **TXT 라벨이 비어 있거나 객체가 0개인 이미지**가 있다면, 그것은 "장비는 NG로 판정했지만 사람이 보기엔 이물이 없는" **장비 과검 사례**일 수 있습니다. 이런 이미지는 **매우 귀한 진짜 음성 샘플**입니다. 반드시 개수를 확인합니다 [추론].
3. **TXT가 없는 BMP를 음성(이물 없음)으로 간주하면 안 됩니다.** 라벨을 달지 않았을 뿐, 이물이 있는 NG 이미지일 가능성이 높습니다 [추론].
4. **음성 샘플 확보 방안**(검토 후 채택한 방법을 보고서에 명시)
   - (a) 객체가 0개인 TXT 이미지
   - (b) 라벨된 이미지에서 이물 bbox를 피해 제품 영역을 잘라낸 패치 단위 음성
   - (c) 이물 영역을 인페인팅해 만든 합성 양품. 단, 인페인팅 흔적이 단서가 되지 않게 처리해야 합니다(§6).
   - (d) 외부 데이터. 공지의 외부 데이터 규칙을 따릅니다.
   - 어떤 방식이든 **평가셋의 음성은 실제 이미지 기반**이어야 FP 수치를 믿을 수 있습니다.

## 4. 데이터 구성과 수량

가이드북 안에서도 수치가 서로 다릅니다. **실측이 필요합니다.**

| 출처 | 내용 |
|---|---|
| 분석요약 표 [명시] | 3,919개(bmp, jpg), 530개(txt), 총 419MB |
| 본문·각주 [명시] | BMP 총 2,809개 / 415MB |
| └ 1호기 | 1,031개 / 112MB (평균 약 109KB/장) |
| └ 2호기 | 920개 / 92.9MB (평균 약 101KB/장) |
| └ 3호기 | 858개 / 210MB (평균 약 245KB/장) |
| 사전 라벨링 세트 [명시] | "라벨링 6종 세트" : 이미지 500개를 미리 라벨링. 15/50/100/200/300/400개 단위 폴더로 구분. 세트별 학습 가중치(last100.pt 등) 포함 |

### 해석 [추론]

- **라벨(TXT)이 있는 이미지는 전체의 약 18~19%(500~530장)** 뿐입니다. 공식 정답은 TXT이므로 **지도학습과 평가에 쓸 수 있는 데이터는 이 범위**로 한정됩니다.
- 나머지 약 2,300장은 라벨이 없습니다. 반지도학습, 의사라벨링, 자기지도 사전학습 등에 쓸 수 있습니다. 단, 이 이미지에도 색상 표시가 있으므로 §6의 처리를 먼저 적용해야 합니다.
- 3,919 − 2,809 = 1,110개는 JPG로 보입니다(실습 중 변환본이나 탐지 결과물). **같은 이미지의 BMP와 JPG가 중복**되어 있을 수 있으므로 해시 기준으로 중복을 제거합니다.
- 라벨링 6종 세트의 폴더들은 **서로 포함 관계일 가능성**이 높습니다(15 ⊂ 50 ⊂ …). 파일명 기준으로 합집합을 만들고 중복을 제거합니다.
- **호기별 평균 파일 크기가 크게 다릅니다**(3호기가 약 2.3배). 해상도나 비트심도(8bit 팔레트 vs 24bit)가 호기마다 다를 수 있습니다.
- 공지에서 요구하는 "테스트데이터 예측결과 파일"에 쓸 **공식 테스트셋이 따로 제공되는지**는 가이드북에 없습니다. 데이터 폴더에서 확인합니다.

## 5. 폴더와 파일명 구조

```
X선이물검출기(06.23_09.22)/          # [명시]
├── 1호기/ (2호기/, 3호기/)            # 설비별 폴더 [명시]
│   └── SN77128_20200622_NgImage/     # 일자별 NG 이미지 폴더 [그림 24] (SN{장비시리얼}_{YYYYMMDD}_NgImage)
│       └── 002_20200622_203053(2).bmp
```

- 가이드북 코드는 `폴더명[17:] == "NgImage"`로 일자 폴더를 찾습니다 [그림 26]. 폴더명 길이가 고정되어 있다는 뜻입니다.
- **파일명 패턴** : `{접두번호}_{YYYYMMDD}_{HHMMSS}({n}).bmp` [그림 1, 24]
  - 접두번호는 `001`, `002`가 관찰됩니다. 호기 번호와는 다른 것으로 보이며(1호기 폴더에 `002_` 파일이 있음), **라인·레인·카메라·제품 구분일 수 있습니다** [추론].
  - `({n})`은 0~9 값이 관찰됩니다. 의미는 알 수 없습니다(순번, 검출 개수 등) [추론].
  - 시각 정보로 촬영 시각을 복원할 수 있습니다. 예를 들어 `…203209`, `…203212`, `…203215`처럼 **약 3초 간격의 연속 저장**이 보입니다 [그림 1]. 같은 시간대에 연속 촬영된 이미지는 같은 제품 로트이거나 비슷한 상황일 가능성이 높습니다.
- **분할 전략에 대한 함의**
  - 가이드북은 이미지 단위로 무작위 8:2 분할을 했습니다 [명시]. 연속 촬영 때문에 **학습/검증 누수 위험**이 큽니다.
  - 이 프로젝트는 **호기 × 일자(또는 시간 창) 단위의 그룹 분할**을 기본으로 합니다.
  - 추가로 **호기별 hold-out**으로 장비 간 일반화도 검증합니다.

## 6. 색상 사각형 표시의 정체 ★ 누수 위험

- 이미지는 "X-RAY상 결함이 **검출되어 표시된** 이미지"입니다 [명시]. 붉은색 상자 중심의 검은 부분이 결함입니다 [명시].
- 즉, **색상 사각형은 기존 검사장비가 자체 판정 결과로 그린 마킹**입니다 [명시 + 추론].
- 색상은 주로 **붉은색**이고, 일부 이미지에서는 **녹색·노란색·보라색 계열**도 보입니다 [그림 1, 10, 11]. 색상별 의미(검출 알고리즘, 감도 단계, 이물 종류 등)는 알 수 없습니다.
- 가이드북의 라벨링 화면을 보면, **사람이 장비의 색상 상자 위에 겹쳐서 TXT bbox를 그렸습니다** [그림 39, 40].
  - 따라서 **TXT bbox 위치와 색상 상자 위치는 거의 일치**할 것입니다.
  - 전처리 없이 학습하면 모델이 "색상 사각형 = 이물"이라는 지름길을 학습합니다. 이것이 대회 추가 공지가 금지한 상황입니다.
- **가이드북의 성능 수치(§9)는 색상 표시가 남은 이미지로 학습·평가한 결과**입니다. 이 프로젝트의 수치와 **직접 비교할 수 없습니다** [추론].

### 전처리 설계 시 주의점 [추론]

1. **그레이스케일 변환만으로는 부족합니다.** 색상 픽셀은 회색으로 바뀌어도 주변과 밝기가 다른 사각형 테두리로 남습니다.
2. **색상 픽셀 검출** : X-ray 원영상은 R=G=B입니다. 따라서 채널 간 차이(예: max−min > 임계값)로 표시 픽셀을 찾을 수 있습니다. BMP가 8bit 팔레트 형식이면 팔레트 인덱스로 정확히 찾을 수도 있습니다.
3. **테두리는 이물 바로 주변을 둘러쌉니다.** 인페인팅하면 이물 주변의 국소 대비가 바뀔 수 있습니다. 대비 기반 조건 분석(§10)을 할 때 이 영향을 따로 점검합니다.
4. **인페인팅 흔적이 새로운 지름길이 될 수 있습니다.** 인페인팅 패턴이 "여기에 상자가 있었다"는 신호가 되기 때문입니다. 대응 방안은 다음과 같습니다.
   - 이물이 없는 위치에도 같은 모양의 가짜 상자를 그린 뒤 인페인팅하는 증강을 적용합니다.
   - 표시가 있던 이미지와 없던 이미지로 나눠 성능을 비교합니다.
   - Grad-CAM 등으로 모델이 테두리 영역이 아니라 이물 중심을 보는지 확인합니다.
5. 일부 이미지에만 표시가 있다면(공지: "일부 BMP"), **표시가 없는 라벨 이미지**를 누수 없는 검증용으로 우선 활용합니다.
6. **장비 마킹과 TXT 라벨의 불일치**는 그 자체로 기존 장비의 미검·과검 정보입니다. 예를 들어 TXT에는 있는데 마킹이 없으면 장비 미검, 마킹은 있는데 TXT에는 없으면 장비 과검일 수 있습니다. 이 불일치를 **데이터 진단과 현장 분석 목적**으로 집계하는 것은 탐지 특징으로 쓰는 것과 다릅니다. 다만 규정 해석의 여지가 있으므로 **보고서에 쓰기 전에 사용자에게 확인**합니다.

## 7. 이미지의 시각적 특성 [그림 기반, 추론 포함]

- **영상** : 단일 채널 투과 X-ray. 배경은 밝은 회색으로 균일하고, 제품은 더 어둡습니다 [그림 2, 25].
- **제품 외형** : 모서리가 둥근 직사각형 포장체입니다. 내부에 **어두운 가로 띠(스틱형 내용물로 추정) 1~3줄**이 보입니다 [그림 1, 2, 25].
- **이물의 모습** : 작은 **어두운 점(고밀도)**입니다. 관찰된 예시는 주로 **어두운 띠의 한쪽 끝부분**에 있습니다 [그림 2, 25, 102]. 이물 위치에 구조적 경향이 있을 수 있으며, 제품·띠 가장자리 조건 분석과 직결됩니다.
- **자세 변화** : 이미지 안에서 제품의 **위치와 회전 각도가 매번 다릅니다**(약 ±20° 범위로 기울어짐) [그림 1].
- **해상도** : 그림 25의 축 눈금으로 보면 약 350×335 px로 추정됩니다. 가이드북의 탐지 로그에서 `001_` 파일은 416×512, `002_` 파일은 512×512로 리사이즈되었습니다 [그림 76]. **접두번호나 호기에 따라 가로세로 비율이 다를 수 있습니다.**
- **이물 크기** : 라벨 예시의 정규화 bbox가 w ≈ 0.026~0.034, h ≈ 0.021~0.036입니다 [그림 43]. 약 350px 기준으로 **한 변 약 7~12 px의 초소형 객체**입니다.
- **이미지당 이물 수** : 여러 개인 경우가 흔합니다(예시에서 3개) [그림 2, 43].

## 8. TXT 라벨 포맷

- **도구** : OpenLabeling, YOLO_darknet 출력 형식 [명시]
- **클래스** : 단일 클래스 `0 = Defect` [명시]. 이물 종류(금속, 비금속 등)는 구분되어 있지 않습니다.
- **형식** : 한 줄에 객체 하나, `class x_center y_center width height`, 0~1로 정규화 [그림 43]
  ```
  0 0.6136363636363636 0.35240963855421686 0.03409090909090909 0.03614457831325301
  0 0.6178977272727273 0.4186746987951807  0.02556818181818182 0.03012048192771084
  0 0.6235795454545454 0.4954819277108434  0.02556818181818182 0.02108433734939759
  ```
- 가이드북 본문에는 좌표 순서가 "(x, y, h, w)"라고 적힌 곳도 있습니다. 예시와 YOLO 표준을 보면 **x, y, w, h 순서로 보입니다.** 실제 이미지 위에 bbox를 그려서 확인합니다.
- 정규화 분모는 원본 이미지 크기입니다. 예시 값으로 역산하면 가로 352px 근처로 보입니다(0.0340909 ≈ 12/352) [추론].
- 이물 종류 라벨이 없으므로, 공지가 요구하는 "형상·밀도" 조건은 **라벨에서 얻을 수 없습니다.** 영상에서 계산한 지표(bbox 종횡비, 국소 최소·평균 밝기, 배경 대비 등)로 대신합니다.

## 9. 가이드북 실험 결과 (참고용 베이스라인, 직접 비교 불가)

| 항목 | 내용 [명시] |
|---|---|
| 모델 | YOLOv3-SPP (ultralytics 계열 PyTorch 구현), **COCO 사전학습 가중치**로 초기화 |
| 입력 크기 | 512 |
| 학습 | epoch 150, batch 5 (라벨 수가 적으면 epoch를 늘림). 지표가 0.9 이상이 되면 학습 중단 |
| 분할 | 이미지 단위 무작위 8:2. 별도로 미학습 테스트 100장 |
| 추론 설정 | detect conf_thres 0.3, iou_thres 0.6 / test conf_thres 0.001 |
| 속도 | 이미지당 0.02~0.03초 (RTX 2060) |

**라벨 수에 따른 테스트 성능** [명시, 그림 87~90]

| 라벨 이미지 수 | 15 | 50 | 100 | 200 | 300 | 400 |
|---|---|---|---|---|---|---|
| mAP@0.5 | 0.772 | 0.828 | 0.738 | 0.933 | 0.978 | 0.948 |
| Precision | 1.000 | 0.904 | 0.762 | 0.924 | 0.951 | 0.949 |
| Recall | 0.112 | 0.515 | 0.768 | 0.950 | 0.983 | 0.962 |
| F1 | 0.202 | 0.657 | 0.765 | 0.936 | 0.967 | 0.955 |

- 가이드북의 결론은 "200장이면 P≈0.92, R≈0.95, F1≈0.93으로 충분하다"입니다.

### 한계와 시사점 [추론]

- **색상 표시가 남은 상태로 학습했고, 무작위 분할을 썼습니다.** 따라서 위 수치는 **누수로 부풀었을 가능성**이 큽니다. 이 프로젝트에서 "가이드북 대비 향상"이라는 식의 비교는 하지 않습니다.
- 가이드북에서 쓸 만한 것은 **경향**입니다. 라벨 수가 적으면 **Recall이 급락**하고 Precision은 유지되었습니다. 즉 데이터가 적으면 **미검이 먼저 늘어납니다.** 라벨 수에 따른 학습 곡선을 보고서에서 다시 검증할 가치가 있습니다.
- 가이드북의 혼동행렬은 **양품을 양성으로** 정의하는 등 표기가 뒤섞여 있습니다. 이 프로젝트에서는 **양성 = 이물(불량)**으로 명확히 정의합니다(FN = 미검, FP = 과검).
- 데이터셋에 포함된 **가이드북 가중치(last*.pt)는 색상 표시로 학습되었을 수 있습니다.** 초기화용으로 쓰지 않습니다.
- COCO 사전학습 가중치를 쓰면 **외부 데이터 활용**에 해당합니다. 보고서에 사유·방법·출처를 명시합니다.
- 가이드북 실행 환경(Python 3.7.3, torch 1.7, CUDA 10.2/11.1)은 오래되었으므로 따르지 않습니다.

## 10. 모델 설계와 분석을 위한 인사이트 요약

| 주제 | 인사이트 | 대응 방향 |
|---|---|---|
| 정답 범위 | TXT가 있는 약 500장만 공식 정답 | 지도학습과 평가는 라벨셋 기준. 라벨 없는 이미지는 보조 용도로만 |
| 음성 부족 | NG만 수집되어 양품이 없음 | 객체 0개 TXT 확인, 패치 단위 음성, 실제 기반 평가 음성 확보(§3) |
| 누수 ① 색상 표시 | 장비 마킹 ≈ TXT bbox 위치 | 표시 제거·인페인팅, 가짜 상자 증강, 표시 유무별 성능 비교(§6) |
| 누수 ② 연속 촬영 | 수 초 간격 연속 저장 | 호기 × 일자·시간 창 그룹 분할, 호기 hold-out(§5) |
| 초소형 객체 | 한 변 약 7~12px | 원해상도 유지나 업샘플, 고해상도 특징맵(P2), 타일링, 작은 앵커 또는 anchor-free |
| 다중 객체 | 이미지당 여러 개 | 객체 단위 Recall과 이미지 단위 판정을 모두 보고 |
| 장비 간 차이 | 호기별 파일 크기와 비율 차이 | 호기별 성능 분석, 입력 정규화 방식 점검 |
| 자세 변화 | 위치·회전 변화 | 회전·이동 증강. 제품 영역 분할로 "가장자리 거리" 계산 |
| 위치 경향 | 이물이 띠 끝부분에 몰림(관찰) | 제품·띠 경계까지 거리 기준의 조건 분석. 중앙과 가장자리 비교 |
| 조건 변수 | 라벨에 크기·형상·밀도 정보 없음 | bbox 면적·종횡비, 국소 대비, 최소 밝기, 경계 거리, 호기, 접두번호, 시간대를 직접 계산 |
| 데이터 효율 | 라벨이 적으면 Recall 급락(가이드북) | 라벨 수별 학습 곡선, 반지도학습·의사라벨 검토 |
| 실시간성 | 현장 요구는 0.02~0.03초/장 수준 | 추론 속도를 함께 보고하고 경량 모델도 비교 |
| 현장 맥락 | 최종검사 단계, 이중·삼중 검사 비용 | 3구간 판정(통과/재검사/배출)과 재검사 비율 대비 미검 감소 효과를 정량화 |
